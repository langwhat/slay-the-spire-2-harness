# Shared execution owns complete decision units

User-requested pausing must occur between complete decisions and their resulting action batches, including settlement and feedback; automatic progression has one action per unit. `Execution.run_unit(source, task)` therefore accepts a model-independent decision source and controls the whole unit, rather than accepting only an already-generated action or requiring each orchestration to assemble the sequence. Orchestration selects the role and task; Run selects automatic progression or its strategy internally from the observation obtained after admission. Both paths return a proposal and receive feedback through the same role interface; agents retain model/tool-loop state and protocol feedback associations, while proposals remain pure business data. This makes execution responsible for invoking a decision, but keeps pause handling and submission order consistent across agents, fixed-code strategies, and automatic progression without binding execution to a model implementation. Atomicity here describes the pause boundary, not rollback or guaranteed completion of every proposed game action.
