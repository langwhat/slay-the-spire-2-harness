# Reading observations

`catalog_additions` gives newly delivered exact content profiles. `scene` gives complete current node bindings; a change in game, run, or node identity invalidates previous node-scoped references. Each supplied `current` section completely replaces its previous section within its valid scope, except the specifically defined complete `card_descriptions` entries below. An omitted section retains its previous value only while valid; a section explicitly set to null clears its prior value. Combat encounter identity stays valid within the same node and battle when a later observation omits it. A change in game, run, or node identity, or leaving combat, invalidates it unless a new encounter is supplied. `decision` is the complete current choice surface, including explicit absence of a selection; never merge an old menu into it. Current complete membership, not a profile, preview, knowledge entry or historical mention, establishes which actual objects are present. Names and native definition IDs identify game concepts; node-scoped references address actual objects and operations. A reference may restart in another node. Within a node a card reference follows the actual card across pile and effect changes. A potion reference follows the actual bottle across slot changes; consuming or discarding it retires that reference, and a newly acquired bottle receives a new one.

A complete card description entry supplies the complete current untargeted native text for that card, including any present battle modifiers and effects other than damage. A new entry replaces that card's prior entry in full; omission preserves it only for an actual member in the current node. Null means its description is unknown now. Membership and node invalidation determine whether the card remains present. Current costs and playability can change independently; they do not imply that its description changed. Target previews give current target-specific text, not a replacement for the untargeted description, a promise of final HP loss, or proof of legality. Avoid applying included modifiers twice; account for changes caused by earlier actions.

For complete card entries only, omitted `local_keywords` equals that entry's `keywords`; an explicitly different local list is complete. Omitted enchantment or affliction means that modifier is absent. An omitted `should_retain_this_turn`, `exhaust_on_next_play`, or `has_turn_end_in_hand_effect` means false; true and unknown are explicitly supplied. These are current behavior, not permanent properties. Modifier identity, localized name, amount, status and description describe its actual owner; equal shared explanation does not merge owners. An explicit replacement or empty list clears the prior contents. Unknown, absence, zero and false have different meanings; do not fill unknown values from older observations.

Costs specify applicable resources. Numeric zero, `X`, `none`, null and a missing resource differ: zero costs zero; `X` follows the card's rules; `none` means no consumption of that resource; null is unknown; a missing resource is not applicable. `cost_without_global_effects`, when provided, retains local modifiers and is not a printed base cost; its omission does not establish a base cost. Current playability is separate from cost. A selection gives its prompt, source, native min and max, complete candidates, and selected references. `selection=null` means no selection; `selected=[]` means none selected. When min is zero, `select` with `refs=[]` completes the choice without taking an option; do not treat this as undoing prior actions.

An upgrade preview belongs to a particular source and describes a hypothetical next upgrade, not an actual instance or action. `not_upgradable` and `unavailable` differ. A generated-card preview belongs to its source, expands one level, and does not create an owned or playable card. Card rewards, shop card offers, and choices whose native purpose is upgrading include the next-upgrade preview when available; other cards require an explicit upgrade inspection. Actual acquisition, upgrading, or generation is established by a subsequent observation. Complete authoritative relation sections can clear prior previews; partial inspections cannot imply removal.

Visible decision-relevant unavailable options remain visible with `enabled=false`, costs and native reasons if supplied. They are not executable until their legality changes; do not invent an absent reason. Execute with the latest actual references and native legality. Explicit detail inspections, knowledge lookups and skill reads return the full requested content every time, even if previously delivered. A state read refreshes current facts; requested detail is in `data` and can become stale after later game changes. A query failure remains a failure. Native definitions and previews do not replace current live instance values.

`outcome` describes the submitted operation. `completed` means the operation finished, not that the run or battle ended; `rejected` means it was not accepted at entry; `stopped` means a known prefix completed and the remaining step stopped; `unknown` means an operation may have taken effect; `failed` means a read failed. Continue from returned facts without repeating completed steps. If no trustworthy observation is available, it is explicitly absent; do not treat an earlier observation as current.
